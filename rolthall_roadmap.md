## Адаптации под реальный хостинг

Исходный план предполагал VPS, но работаем на **Beget Great (shared)**:

| Было в плане | Реальное решение |
|---|---|
| PostgreSQL 16 | MySQL 5.7 (strict=false, defaultStringLength=191) |
| Redis TTL для hold | DB-очередь + Scheduler каждую минуту |
| Supervisor + воркеры | CronTab → php artisan schedule:run |
| Next.js сервер | Пока лендинг на PHP, Next.js — позже |
| Redis сессии | DB/file сессии |

---

## Почему именно такая последовательность

Проект строится по принципу **«работающий слой за слоем»**:  
клиент видит и тестирует реальный результат после каждого этапа, а не ждёт 3 месяца финального деплоя.

```
Инфраструктура → Данные → Каталог → Бронирование → Оплата → Управление → Запуск
```

Каждый следующий этап опирается на предыдущий — нельзя строить оплату без бронирования,
нельзя строить бронирование без тарифного движка.

## Этап 1 — Фундамент (54 ч / ~96 000 ₽ / Оплата 20%)

### Что делается
- **Сервер**: Beget VPS, Nginx (роутинг /api → Laravel, /* → Next.js), PHP 8.3, PostgreSQL 16, Redis, SSL
- **Laravel**: инициализация, структура Services/Models/Jobs, Sanctum аутентификация, Spatie Roles — все 4 роли (`developer`, `landlord`, `admin`, `client`)
- **База данных**: все миграции из `rolthall_dev_skill.md` — `halls`, `bookings`, `pricing_rules`, `clients`, `action_logs`
- **Next.js**: App Router, TailwindCSS, дизайн-система (цвета Charcoal + #376FFF, шрифт Unbounded), базовые UI-компоненты, Zustand + React Query

### Зачем первым
Без этого нечего запускать. После этапа — рабочий dev-стенд, можно регистрироваться, видеть пустой каталог. Даём клиенту ссылку на staging.

### Риски
- Beget может иметь ограничения по конфигурации — заложено время на выяснение
- Если клиент захочет сменить хостинг — +4–6 ч

---

## Этап 2 — Каталог, Тарифы, Календарь (80 ч / ~141 000 ₽ / Оплата 25%)

### Что делается
- **Каталог залов**: API halls + фото (локальный storage через Nginx alias), фронт — карусель Swiper.js, фильтры, карточки залов
- **Тарифный движок**: `PricingService::calculate()`, таблица `pricing_rules`, API /api/halls/{id}/pricing, клиентский `pricing.ts` с расчётом в реальном времени, страница тарифов с калькулятором
- **Время-слоты**: интерактивный тайм-грид (выбор начала + конца), live-расчёт суммы и предоплаты, bottom sheet
- **Hold логика**: `POST /api/bookings/hold` → Redis `setex key 600`, Scheduler `ReleaseHoldJob` — каждую минуту, `GET /api/halls/{id}/availability`

### Зачем вторым
Это «сердце» продукта — без него нечего продавать. После этапа клиент может пройти путь до экрана «оформить бронь» и увидеть правильные цены. Оплаты ещё нет — тестируем логику безопасно.

### Почему Hold делается здесь, а не с оплатой
Hold нужен до оплаты — именно он резервирует слот на 10 минут и даёт время ввести карту. Без Hold нет смысла запускать страницу оплаты.

### Риски
- Алгоритм определения доступных слотов (пересечения, буфер между бронями) — самое сложное место, заложено время на edge-cases

---

## Этап 3 — Оплата и Уведомления (71 ч / ~125 000 ₽ / Оплата 20%)

### Что делается
- **CloudPayments**: `PaymentService` — инициирование, обработка webhook (HMAC-подпись), tokenization (сохранение карты в CP Vault), повторный платёж, автоматический возврат через API CP
- **Правила возврата**: отмена ≥6 ч до начала → полный возврат предоплаты; <6 ч → возврат не делается
- **Frontend**: виджет CloudPayments (карта + СБП), 50% предоплата, экран успеха
- **Telegram Bot**: настройка webhook, `NotificationService` со всеми шаблонами (новая бронь, подтверждение, напоминания 24ч/2ч, отмена), Queue Jobs, Email fallback

### Зачем третьим
Нельзя принимать оплату без рабочего hold и слот-движка — деньги спишутся, а слот может оказаться уже занятым. После этапа — полный цикл: выбрал зал → забронировал → оплатил → получил уведомление в Telegram.

### Важно по CloudPayments
Разрабатываем и тестируем в тестовом режиме CP — нет реальных списаний до финального QA. Webhook-endpoint должен быть на HTTPS с реальным доменом (не localhost) — поэтому деплой на staging делается в конце этапа 1.

## Этап 4 — Личный кабинет и Админ-панель (72 ч / ~127 000 ₽ / Оплата 20%)

### Что делается
- **Личный кабинет клиента**: активные брони + история, статусы таймлайном, отмена (с проверкой 6ч), запрос переноса, повтор бронирования, профиль (телефон, email, telegram), сохранённые карты
- **FilamentPHP 3**: список броней (фильтр + поиск), CRM-карточка (вся история клиента + контакты + заметки), ручная бронь и override, блэклист клиентов
- **Аналитика в Filament**: выручка (день/неделя/месяц), загрузка залов в %, популярные часы (тепловая карта), повторные клиенты
- **Action Logs**: `ActionLogger::log()` — immutable запись каждого действия (`user_id`, `role`, `action`, `target`, `payload`, `ip`), viewer в Filament

### Зачем четвёртым
FilamentPHP выбран намеренно: он даёт готовый CRUD, фильтры, роли и формы за 1/3 времени кастомной разработки. Его нельзя ставить раньше — нужно знать все модели и связи.

### Зачем аналитика здесь
После этапа 3 появляются реальные данные (или тестовые брони). Аналитика требует рабочих данных для тестирования — иначе не проверишь корректность запросов.

## Этап 5 — Арендодатель, Безопасность и Запуск (71 ч / ~125 000 ₽ / Оплата 15%)

### Что делается
- **Панель арендодателя**: дашборд по своим залам, CRUD залов с фото, блокировка дат, редактор тарифных правил без деплоя
- **Безопасность**: Honeypot + Time Trap в формах, Laravel Throttle, роль-гарды на все маршруты
- **Юридические страницы**: 6 документов (оферта, конф. политика, правила аренды, правила возврата, ОПД, согласие), логирование согласий при оформлении
- **Тестирование**: PHPUnit unit + feature тесты (PricingService, BookingService, webhook), ручное QA на iPhone/Android/desktop
- **Деплой**: production Beget, Supervisor, PM2, cron, сидинг, документация

### Зачем последним
Панель арендодателя строится поверх готового API — нет смысла делать её раньше. Безопасность тестируется на финальном функционале. Деплой — последний шаг, когда всё протестировано.

## Как вести разработку максимально быстро

### 1. Backend и Frontend параллельно
API и фронт можно разрабатывать одновременно через **мок-данные** (MSW или hardcoded fixtures).
Это экономит 15–20% времени на каждом этапе.

### 2. Feature Branches + Staging
Каждая фича идёт в отдельную ветку. Staging на Beget обновляется автоматически (GitHub Actions или простой `git pull` по webhook). Клиент тестирует в реальном времени — нет задержек на «покажи что есть».

### 3. FilamentPHP вместо кастомного admin
FilamentPHP 3 экономит ~60 часов на CRUD-интерфейсах для admin. Компромисс: меньше дизайн-кастомизации, но полный функционал из коробки.

### 4. CloudPayments тестовый режим с первого дня
CP предоставляет тестовые карты. Не ждём `этапа 3` для интеграции — накидываем заглушку `PaymentService` в этапе 2, заполняем реальной логикой в этапе 3.

### 5. Приёмка через чеклист
Для каждого этапа — конкретный список сценариев, которые клиент проверяет сам. Нет расплывчатых «всё работает» — есть «нажми вот это, должно случиться вот то».

## Стек решений и обоснование

| Решение | Альтернатива | Почему выбрано |
|---|---|---|
| FilamentPHP 3 | Кастомный admin | -60ч, готовые роли/фильтры/логи |
| Redis TTL для Hold | Laravel Scheduler поллинг | Надёжнее: TTL срабатывает точно в момент, не зависит от задержки очереди |
| CloudPayments | ЮKassa, Тинькофф | Лучшая Laravel-интеграция в РФ, готовый SDK, tokenization, поддержка |
| PostgreSQL | MySQL | JSONB для equipment/photos, лучший full-text search для CRM |
| Beget VPS | Timeweb, reg.ru | Стабильный по опыту в РФ, Redis addon, PHP 8.3 из коробки |
| Telegram Bot | SMS, Push | Бесплатно, 100% доставляемость, клиент просит именно это |

## Риски и митигация

| Риск | Вероятность | Митигация |
|---|---|---|
| CP webhook не проходит за NAT/firewall | Средняя | Staging сразу на реальном домене с HTTPS |
| Beget ограничивает Redis (только localhost) | Низкая | Проверяем в этапе 1, при необходимости redis addon |
| Клиент меняет требования в ходе разработки | Высокая | Всё сверх скоупа = отдельный расчёт по ставке 1760 ₽/ч |
| Сложная логика конфликтов слотов | Средняя | Покрыто тестами в этапе 2, buffer-параметр в настройках |
| CloudPayments меняет API | Низкая | Используем официальный Laravel SDK, не raw API |

## Что не входит в смету

- Контент (фото залов, тексты, описания) — предоставляет клиент
- Создание юридических текстов документов — предоставляет клиент или юрист
- Домен и SSL-сертификат — оплачивает клиент (~1 500 ₽/год)
- Beget VPS тариф — оплачивает клиент (~3 000–5 000 ₽/мес)
- SEO, маркетинг, соцсети — вне скоупа
- Мобильное приложение (iOS/Android native) — отдельный проект
