# Требования к проекту — RoltHall Booking Platform

## 1. Общее описание

Production-ready платформа онлайн-бронирования танцевальных залов с CRM, административной панелью, эквайрингом и Telegram-уведомлениями.

Хостинг: **Beget** (облачный VPS, Ubuntu 22.04 LTS)

---

## 2. Роли пользователей

| Роль | Описание |
|---|---|
| `developer` | Полный доступ. Системные настройки, управление ролями, просмотр всех логов |
| `landlord` | Арендодатель. Создаёт залы, блокирует даты, настраивает тарифы, видит аналитику |
| `admin` | Администратор. Управляет бронями, клиентами, CRM, ручные брони |
| `client` | Клиент. Бронирует залы, видит свой личный кабинет, историю, оплаты |

Система permissions-based: права назначаются отдельно для каждой роли через FilamentPHP.

## 4. Серверная конфигурация (Beget)

```
/var/www/rolthall/
├── backend/          # Laravel приложение
│   ├── app/
│   ├── storage/
│   └── ...
└── frontend/         # Next.js (собранный билд)
    ├── .next/
    └── ...
```

**Nginx роутинг:**
- `/api/*` → Laravel (PHP-FPM, порт 9000)
- `/*` → Next.js (PM2, порт 3000)

**Важно для Beget:**
- Использовать Beget CDN для статики (фото залов)
- Хранение медиафайлов: локально `/storage/app/public` + Nginx alias
- Для очередей: Redis через Beget Redis-addon или localhost

## 5. Pricing Engine

### Логика тарифов

Тарифы задаются через Admin Panel (FilamentPHP). Структура:

```
Тариф:
- Дни недели: [Пн, Вт, Ср, Чт, Пт] | [Сб, Вс]
- Диапазоны часов:
  - от 1 ч: X ₽/час
  - от N до M часов: Y ₽/час
  - от K часов: Z ₽/час
```

### Пример конфигурации

| Дни | Длительность | Цена/час |
|---|---|---|
| Пн–Пт | 1 час | 1 000 ₽ |
| Пн–Пт | 4–6 часов | 800 ₽ |
| Пн–Пт | от 8 часов | 600 ₽ |
| Сб–Вс | 1 час | 1 200 ₽ |
| Сб–Вс | 4–6 часов | 1 000 ₽ |
| Сб–Вс | от 8 часов | 800 ₽ |

### Отображение клиенту
При выборе времени — показывается таблица тарифов для выбранного зала и дня недели. При изменении длительности цена пересчитывается в реальном времени.

## 6. Booking Engine

### Статусы брони

```
draft → hold (10 мин) → pending_payment → paid → confirmed → completed
                                        ↓
                                    cancelled
```

| Статус | Описание |
|---|---|
| `draft` | Клиент начал, не выбрал время |
| `hold` | Слот зарезервирован на 10 минут |
| `pending_payment` | Ожидает оплаты предоплаты (50%) |
| `paid` | Оплата прошла |
| `confirmed` | Подтверждено администратором |
| `completed` | Завершено |
| `cancelled` | Отменено |

### Hold логика
- После выбора времени слот блокируется на **10 минут** через Redis TTL
- Если оплата не завершена → автоматически освобождается (Laravel Scheduler)

### Buffer между бронями
- Настраиваемый (по умолчанию 0 минут, можно задать 15–30 мин)

---

## 7. Оплата

- **Предоплата: 50%** от суммы аренды
- Интеграция: **CloudPayments** (эквайринг)
- Карта не хранится — только **payment token** (CloudPayments Vault)
- Автоматические возвраты через API CloudPayments

### Правила отмены
- Отмена ≥ 6 часов до начала → предоплата возвращается
- Отмена < 6 часов → предоплата не возвращается

## 11. Scheduler — автоматические задачи

| Задача | Интервал |
|---|---|
| Снятие hold по истечении 10 мин | каждую минуту |
| Отправка напоминаний (24ч, 2ч) | каждые 15 минут |
| Перевод завершённых броней в `completed` | каждые 15 минут |
| Cleanup expired draft броней | каждый час |
| Автоматические возвраты | по событию |
